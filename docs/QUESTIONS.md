8. **(M1) `docker run` is denied** by project permissions, so integration tests reach pg1 via its bridge IP (`make itest`) instead of a throwaway container.
9. **(M1) pg_hba.conf.** The stock postgres image allows `scram-sha-256` from any address; PRD 9 requires the Compose subnet only. Deferred to M2, which ships its own `pg_hba.conf`. Until then Postgres is reachable only on the internal Compose network (no published port).
10. **(M1) Reviews.** go-reviewer, security-reviewer and database-reviewer ran. Fixed: encoded-path bypass of the HAProxy /debug deny, NUL/invalid-UTF-8 input (400 not 500), statement-timeout and cancel mapping, /debug/crash flush, alloc race, route label, schema_migrations grant, .dockerignore, CI random password, golangci-lint pin. Not fixed (low): healthcheck ignores LISTEN_ADDR, trailing JSON after the body is accepted, `app` keeps UPDATE/DELETE (PRD says DML) and PUBLIC TEMP.
11. **(M2) Postgres base image is Debian, not Alpine.** `postgres:17.9-bookworm` (tag verified with `docker manifest inspect`) because the PGDG apt repository in the official image ships `postgresql-17-repmgr` (5.5.0) and `pgbackrest`; the Alpine image has no matching packages. Old M1 volumes (uid 70) are incompatible: run `make nuke` once.
12. **(M2) Fixed Compose subnet 172.30.77.0/24.** PRD 9 wants pg_hba limited to the Compose subnet, so the subnet is pinned in compose.yaml and pg_hba.conf. If it collides with another Docker network on a host, change both.
13. **(M2) `local` pg_hba line.** PRD 9 says "scram-sha-256 from the Compose subnet and nothing else". The Unix socket inside the container is also allowed (scram-sha-256, no trust/peer) because the entrypoint, healthcheck and `docker exec` need it; it is not reachable from the network.
14. **(M2) Docker restart policy after `kill`.** Measured: a container killed with `docker compose kill -s SIGKILL` stays `exited` with `restarts=0` under `restart: unless-stopped` (docs/evidence/M2.md). This is the behaviour PRD 7.3 expects; M4 should still confirm it through dockerproxy.
15. **(M2) Beyond the PRD fencing rule.** PRD 6.4 step 3 only checks the peer at start. Added: a running primary yields if the peer is primary on a newer timeline (covers start-up races and out-of-band promotion), and an empty `PG_ROLE=primary` node clones instead of `initdb` when the peer is already primary. Both chosen to protect "never more than one primary".
16. **(M2) archive_command is `/bin/true`** until M5 wires pgBackRest (`archive_mode=on` already, since changing it needs a restart).
17. **(M2) `repmgr standby switchover` is not supported** (needs SSH between nodes). The runbook's manual failover is stop-old-primary + `repmgr standby promote`.
