14. **(M2) Docker restart policy after `kill`.** Measured: a container killed with `docker compose kill -s SIGKILL` stays `exited` with `restarts=0` under `restart: unless-stopped` (docs/evidence/M2.md). This is the behaviour PRD 7.3 expects; M4 should still confirm it through dockerproxy.
15. **(M2) Beyond the PRD fencing rule.** PRD 6.4 step 3 only checks the peer at start. Added: a running primary yields if the peer is primary on a newer timeline (covers start-up races and out-of-band promotion), and an empty `PG_ROLE=primary` node clones instead of `initdb` when the peer is already primary. Both chosen to protect "never more than one primary".
16. **(M2) archive_command is `/bin/true`** until M5 wires pgBackRest (`archive_mode=on` already, since changing it needs a restart).
17. **(M2) `repmgr standby switchover` is not supported** (needs SSH between nodes). The runbook's manual failover is stop-old-primary + `repmgr standby promote`.
18. **(M2) Base image moved to `postgres:17.12-bookworm`** (tag verified with `docker manifest inspect` on 2026-11-16). With the 17.9 tag, installing repmgr upgraded `postgresql-17` to 17.12 from PGDG, so the server was already 17.12 while the tag said 17.9. The Dockerfile now holds `postgresql-17` and `postgresql-client-17`, so a rebuild fails instead of drifting. Supersedes the tag in item 11. CI's unit-test Postgres is still `17.9-alpine3.23`.
19. **(M2) repmgr and pgBackRest apt packages are not version-pinned** (installed: repmgr 5.5.0+debpgdg-3.pgdg12+2, pgbackrest 2.60.0-1.pgdg12+1). PGDG serves only the newest build of each package, so an exact pin would break rebuilds; a rebuild can therefore pick up a newer repmgr. Chosen: leave unpinned, record versions in evidence.
20. **(M2) Passwords are container environment variables**, so `docker inspect` shows them (security review, MEDIUM). PRD 9 prescribes `.env`; nothing can call inspect today. M4 gives `blast` inspect through dockerproxy: decide there whether to move to Compose `secrets:`.
